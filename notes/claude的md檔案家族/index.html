AI與Claude工具 記於 2026-07-14

Claude 的 .md 檔案家族

用 Claude 時會遇到一堆 .md 檔，各有各的用途。一句話分野：README 寫給人看、CLAUDE.md 寫給 AI 看。 搞懂這條線，其他就好記。

設計師比喻：README 是給客戶看的「作品說明卡」；CLAUDE.md 是你貼在工作桌上、只給自己（和助理）看的「這個案子的規矩便條」。

本篇目錄：0. README vs CLAUDE.md　1. 指令階層（commands／agents／SKILL.md／MEMORY.md）　2. 進階用法　3. @ 引入語法　4. 心法

0. 先分清楚：README vs CLAUDE.md

README.mdCLAUDE.md
寫給誰人（接手的人、三個月後的自己）AI（Claude 每次進資料夾自動吃進去）
內容專案是什麼、怎麼裝、怎麼跑、架構、雷點規則、禁區、慣例、觸發語
用途介紹、交接指揮 Claude 怎麼做這個案子

一句話：README 說明專案，CLAUDE.md 指揮 Claude。 兩者不衝突，可以並存。

專案交接放哪？ 放 README（給人的）。內容多就 README 當入口，細節拆到 docs/（ARCHITECTURE.md、DEPLOYMENT.md…）。CLAUDE.md 不是交接文件，但值得一起交——等於把「怎麼指揮 AI 做這案子」也交出去。

1. 核心：指令階層（給 AI 看，越下面越優先）

Claude 讀規則是疊加的，四層由上往下、越具體越贏：

  1. managed policy — 企業管理員設定，最高、個人不可覆蓋（自己用通常碰不到）
  2. ~/.claude/CLAUDE.md — 全域個人偏好，所有 project 都套用
  3. 專案根/CLAUDE.md — 該 project 的規則（蘇的學習庫「Claude 爸」路由表就是這個）
  4. 子資料夾/CLAUDE.md — 進到那層才載入的局部規則
  5. CLAUDE.local.md — 只在你本機、不進 git 的私人規則

衝突時：越具體的越優先（Project 蓋過全域，但不是取消，是覆蓋那一條）。

相關細節見 Claude_Skill儲存與指示疊加（疊加機制、session 中途改不會重讀）。

2. 進階（用到再學）

  • .claude/commands/*.md — 自訂斜線指令。放一份 .md 進去，打 /檔名 就執行裡面的 prompt。你手動觸發。
  • .claude/agents/*.md — 自訂 subagent，frontmatter 設定要用哪個模型、哪些工具。
  • 各 skill 的 SKILL.md — 技能入口，Claude 依 description 自己判斷要不要觸發（蘇裝的 obsidian-inbox、whoami 都是這種）。
  • MEMORY.md — 跨 session 記憶的索引檔，Cowork 自動維護，通常不用手改。

commands vs skills 差在觸發：commands 是「你自己打 / 叫出來」；skills 是「Claude 讀情境自動決定要不要用」。

3. 語法小技巧：@ 引入其他檔

在 CLAUDE.md 裡寫 @ops/deploy.md，Claude 會把那份內容一起吃進來。好處：主檔保持精簡、細節模組化拆檔。蘇的學習庫「主檔當路由表、細節放子檔、需要才載入」就是這個概念的實作。

4. 心法

CLAUDE.md 每個 session 都吃 context，塞太多會稀釋重點。所以主檔當路由表，細節用 @ 拆出去、需要才載入——精簡才有效。
