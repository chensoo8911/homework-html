Claude Skill 儲存與指示疊加

拆自「Claude運作與設定大全」，只留「skill 存哪／怎麼打包」＋「CLAUDE.md 怎麼疊加」這塊

Skill 儲存與打包機制

Skill 存在哪

  • 每個 session 看到的 skill 路徑是唯讀快取，每次 session 重建（/var/folders/.../skills）。改快取沒用，下次 session 會被覆蓋。
  • 每個 skill = 一個資料夾 + 一個 SKILL.md（描述觸發條件與操作說明）。

Cowork vs Claude Code（機制同、儲存分開）

Cowork 全域Claude Code
來源管理Settings → Capabilities（UI）直接放檔到資料夾
個人 skill 路徑App 內部管理（唯讀快取）~/.claude/skills/
專案 skill 路徑選定 project 的 .claude/skills/專案 .claude/skills/
編輯方式從 UI 操作編輯器直接改 .md
  • 兩邊不會自動互通；同一 plugin 兩邊各裝一份才會「都有」。
  • Cowork 只認兩個固定位置自動載入 skill：① App 啟動時載入「已安裝」的、② 專案資料夾有 .claude/skills/某skill/SKILL.md。不會亂掃整台電腦。

自己做的 skill 要顧什麼

  • 不用管：檔案放哪、路徑、載入時機 → App 自動處理。
  • 要顧：description（決定何時觸發，別寫太模糊）、指令內容正確、避免多個同類 skill 觸發詞打架。

打包與分享

方式適合安裝
.skill 檔（skill 資料夾壓 zip 改副檔名）單一 skill 快速分享對方點「Save skill」
Plugin / Marketplace多 skill ＋ MCP 成套從 marketplace 裝

全域指示 vs Project CLAUDE.md（怎麼疊加）

  • 每個 Project 都會自動載入全域 Global Instructions，不用手動帶。機制是疊加：
    • 全域 → 適用所有任務／Project／排程，session 開始時載入。
    • Project（資料夾）指示 → 只在該 Project 內，進入時疊加上去。
  • 衝突時：愈具體愈優先 → Project 指示 > 全域指示（覆蓋，不是取消全域）。
  • ⚠️ CLAUDE.md 是 session 開始時讀進記憶（載入一次）。session 中途存的新版本，當前對話不會自動重讀 → 要生效得開新 session，或請 Claude「依新的 CLAUDE.md 重新對齊」。
  • 最佳實務：通用規則（語言、語氣、Scannable 格式）放全域讓各專案繼承；專案專屬內容放該 Project 的 CLAUDE.md，不必每個專案重抄。
