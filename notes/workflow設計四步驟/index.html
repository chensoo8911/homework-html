Workflow 設計四步驟

拆自「Skill與自動化全解」Part 3

Workflow＝完成一個專案的整套流程那條線。Command / Skill / SOP / 腳本 是零件，Workflow 是把它們串起來的線。

四零件在 workflow 裡的角色

零件角色工程師專案比喻
SOP開發規範：先做什麼、原則是什麼專案開發守則 / 規格文件 📄
Command啟動開關：敲指令，流程開始跑終端機敲 npm run start ⌨️
Skill需要動腦的工序：要判斷思考的步驟動腦設計架構、解 bug 🧠
腳本固定的自動化粗活：每次一樣自動跑自動跑測試、打包、部署 🤖

它們不是誰取代誰，而是分工合作組成一條開發流程。真功夫是「把它們串成 workflow」。

黃金原則：從「終點」倒推

最常見錯誤是一開始就想「要用哪個工具」。正確相反——先想終點，再倒推步驟（像導航先輸入目的地）。

順序描述什麼自問對應零件
① 終點最後要的成果長怎樣跑完我會拿到什麼？（先定目標）
② 起點何時、怎麼啟動誰按開關？何時跑？Command
③ 中間步驟哪步動腦、哪步固定這步需要判斷嗎？Skill / 腳本
④ 規範輸出格式、存哪、原則結果長怎樣、放哪？SOP

口訣：終點 → 起點 → 中間 → 規範

範例：每天自動生設計趨勢摘要

① 終點：每天早上拿到「3 條設計新聞 + 重點」的筆記
② 起點：每天早上 8 點自動啟動
③ 中間：抓新聞(腳本) → 篩選整理重點(Skill)
④ 規範：用 Obsidian 筆記格式，存到「收件匣」資料夾

整條 ①→④ 就是一個 workflow，SOP 在背後規定格式與存放位置。寫好 ①～④ 的白話描述，它本身就是一份 SOP，要實作時直接貼給 Claude 即可。
