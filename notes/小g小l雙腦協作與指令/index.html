AI與Claude工具

小G小L 雙腦協作與指令（Gemini 苦力 × NotebookLM 圖書館員 × Claude 審查主廚）

記錄日期：2026-07-16（部署完成於 2026-07-10） 概念：Gemini 當量產苦力、NotebookLM 當圖書館員、Claude 當審查主廚——像設計團隊裡「助理先出 20 版草稿，資深設計師挑毛病定稿」的分工。

本篇目錄：一、三個角色分工　二、小G日常三步流程　三、同一 session 三種玩法　四、小L玩法（4.1 中文指令／4.2 底層 notebooklm CLI 指令）　五、什麼事交給誰　六、環境備忘

一、三個角色分工

工具角色怎麼叫它
小G（Gemini）苦力：量產程式碼、分析大量文字、狂寫測試終端機打 小G 問題
小L（NotebookLM）圖書館員：吞規格書 PDF／網址，給有根據的答案、規格小抄、語音導覽終端機打 小L 說明 看用法
Claude Code主廚：審查產出、抓漏洞、最終定稿、寫入檔案、跑測試平常的 Claude Code 對話
共同記憶資料夾三個 AI 交接工作的暫存區~/Claude/雙腦協作/

二、日常三步流程（小G）

步驟一：終端機叫小G做粗活，結果直接存進暫存檔：

小G 今天天氣如何   # 或 小G：今天天氣如何，都不用打引號

說明：小G 會自動落檔到 gemini_review.md；小G 還會自動備援，主通道塞車時自己切換備用通道，看到「改走直連通道」的提示是正常現象。

步驟二：回到 Claude Code，只要打一個 .（句點）。

步驟三：Claude 自動讀取 gemini_review.md，回覆兩段：

  • 漏洞/死角審查：Gemini 漏掉的邊界條件、安全或效能問題
  • 終極修正案：Claude 重構後的定稿，需要時直接寫入專案檔案並跑測試

三、同一個 session 可以怎麼玩（三種玩法）

玩法怎麼做適合
① 叫我去叫小G（最推薦）在 Claude Code 對話直接說「叫小G幫我生 10 個標語」→ Claude 代跑指令、拿到產出、審查完交件日常小事，一句話搞定
② ! 直通終端機在 Claude Code 輸入框打 ! 小G：問題（驚嘆號＋空格開頭）→ 跳過 Claude 直接執行，結果進對話、Claude 也看得到想自己下指令但不想切視窗
③ 開兩個視窗（原始設計）終端機跑 小G ... > gemini_review.md 落檔 → Claude Code 打 . 觸發審查Gemini 產出很長、想先自己過目

記住分工：小G 是純文字大腦，看不到你的電腦；「檢查本機○○」這類問題要問 Claude。

四、小L（NotebookLM）玩法

小L 跟小G 的差別：小G 憑「腦中知識」回答；小L 只根據你餵它的文件回答（有出處、不瞎掰），適合規格書、合約、長文件——像圖書館員只回答書架上有的書，不會憑印象亂講。

4.1 小L 中文指令（日常用這個就好）

指令做什麼
小L 清單看你所有 NotebookLM 筆記本
小L 用 名稱切換到某本筆記本（名稱打部分就行）
小L 加入 檔案或網址餵文件（PDF、txt、網頁連結都吃）
小L：任何問題針對筆記本內容問答（附出處編號）
小L 摘要提煉規格小抄 → 自動存 spec_summary.md 給 Claude 當開發小抄
小L 播客把筆記本做成語音導覽 mp3（要等幾分鐘）

典型流程：小L 用 某專案 → 小L 加入 規格書.pdf → 小L 摘要 → 回 Claude Code 開工，Claude 自動讀小抄。

4.2 底層 notebooklm CLI 指令（小L 中文指令背後實際跑的東西）

非官方 NotebookLM 命令列工具（notebooklm-py），已裝在 Mac 上。在「終端機」直接輸入指令使用。

指令做什麼
notebooklm list列出所有筆記本
notebooklm use 名稱切換到某本筆記本（打部分名稱或 ID 就行）
notebooklm ask "問題"對目前筆記本提問
notebooklm status看目前在哪本筆記本
notebooklm create "新筆記本"建立新筆記本
notebooklm doctor檢查登入狀態是否正常
notebooklm login重新登入（登入失效時才需要）
notebooklm --help完整功能清單（含生成播客、測驗等）

使用邏輯：像「先走進一個房間再說話」——先用 use 選定筆記本，之後的 ask 都是問那一本的內容。也可以直接請 Claude 代為操作（例：「幫我問 NotebookLM 的某某筆記本…」）。

⚙️ 小雜工鐵則：小G／小L 的產出一律自動落檔（gemini_review.md／notebooklm_review.md，帶時間戳＋問題）。Claude 派工給他們時走「安靜模式」，對話只收一行「完成＋字數」——雜工不准浪費指揮官的資源；你自己在終端機手打不受影響，照樣印全文。

五、什麼事交給誰

情境交給誰原因
「幫我生 30 個測試案例」「翻譯這一大篇」小G（Gemini）量大、便宜、不用太聰明
「這段程式碼有沒有問題」「幫我改到能上線」Claude需要判斷力和動手改檔的權限
超長規格書先摘重點小L → 存 spec_summary.md摘完 Claude 再讀小抄，省 token

六、環境備忘（出問題時看這裡）

  • 小G 別名與金鑰設定在 ~/.zshrc（有備份）；小L 本體是 notebooklm-py，指令在 ~/.local/bin/notebooklm，包裝腳本在 ~/Claude/雙腦協作/小L.sh
  • 小L 走 Google 非官方 API，哪天突然壞掉屬正常能量釋放，叫 Claude 修；登入失效時終端機跑 notebooklm login
  • 免費額度：主模型每分鐘 20 次請求，狂刷看到「稍後再試」等一分鐘就好；小G 塞車時會自動切備用模型，看到「改走直連通道」提示屬正常
