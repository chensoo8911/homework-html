AI與Claude工具 記於 2026-07-16

Claude Code 網站建置SOP

來源：YouTube 影片筆記整理（2026-07-16）　用途：用 Claude Code 做出有品牌感、不像 AI 隨手生成的網站 逐步操作版，重點摘要見 Claude建站品牌感技巧（同一支影片的濃縮筆記）。

事前準備

工具用途
VS Code寫程式碼的編輯器
Claude Code（VS Code 擴充套件）需要 Pro/Max 訂閱
frontend-design skill官方 plugin，已裝好，前端設計自動更專業
Puppeteer讓 AI 自動截圖比對瀏覽器畫面
GitHub存放程式碼、版本控制
Vercel接 GitHub 自動部署成正式網站
21st.dev / Dribbble / Godly / Awwwards找網站視覺靈感

步驟 0：建 CLAUDE.md

專案資料夾裡放一份 CLAUDE.md，當作這個網站專案的「系統提示詞」。內容要精簡，寫清楚：

  • 這個專案的目標與風格方向
  • 「每次寫前端程式碼前，一定要先呼叫 frontend-design skill，沒有例外」
  • 截圖工作流程規則（見步驟2）
  • 品牌資產放在哪個資料夾（見下方）

這份檔案不是一次寫完，做的過程中會一直回來補。

步驟 1：準備品牌資產＋下第一個提示詞

  1. 建一個 brand_assets 資料夾，放進去：Logo、品牌規範文件（色票、字體、圖示）
  2. 跟 Claude Code 說：「幫我做一個現代、專業的[品牌名]形象頁，這是我的 Logo 和品牌規範」
  3. 在對話框打 @ 可以直接標記指定檔案給它看，避免檔名不直覺被忽略
  4. 因為已經裝了 frontend-design skill，Claude Code 會自動呼叫它來生成排版/動效

步驟 2：設定截圖迴圈（Screenshot Loop）

在 CLAUDE.md 裡跟 Claude Code 說「幫我用 Puppeteer 設定截圖流程」，它會自己裝好工具。之後每次建站，它會自動：

  1. 寫程式碼 → 開本機伺服器
  2. 截圖比對「做出來的樣子」跟「你要的樣子」
  3. 抓落差、修正、再截圖，重複兩輪左右

⚠️ 注意：遇到動態背景動畫的區塊，截圖比對容易卡住（AI 一直覺得沒做好、越改越糟）。這種情況直接跟它說：「這段不要用截圖工具比對，直接改程式碼就好」。

步驟 3：拿別的網站當範本（整頁複製）

  1. 找到喜歡的參考網站
  2. 瀏覽器開發者工具（Mac 版功能位置需自行查詢對應鍵位）截一張全頁截圖
  3. 到 Elements 面板複製它的 CSS 樣式碼
  4. 把「截圖＋樣式碼」一起丟給 Claude Code：「照這個做一個一樣的網站」
  5. 做出來的架子滿意後，再叫它套用你自己的品牌色/Logo/文案：「用我的 brand_assets 裡的色系跟 Logo，把這個複製版換成我們的風格」

步驟 4：借用單一元件（局部靈感）

不用整頁複製，只针對單一元件（按鈕特效、背景動畫）：

  1. 去 21st.dev 找喜歡的元件，複製它給的程式碼片段
  2. 跟 Claude Code 說：「把這段效果套進[某個區塊]」＋貼上程式碼片段

步驟 5：上線部署

  1. GitHub 建一個新 repo
  2. 跟 Claude Code 說：「把這個專案 push 到 GitHub repo [repo名]」（它會處理登入授權、.gitignore）
  3. 去 Vercel.com 用 GitHub 帳號登入 → Add New Project → 選剛剛那個 repo → Deploy
  4. 之後每次要正式更新網站：先在本機（localhost）測試滿意，才明確跟 Claude Code 說「push 到 GitHub」——GitHub 更新後 Vercel 會自動抓去部署，不用手動操作

⚠️ 注意：CLAUDE.md 裡要寫清楚「除非我明確說 push/commit，否則不要自動推上 GitHub」，避免壞版本自動上線。

額外注意事項

  • 影片中示範用「bypass permissions mode」（跳過權限確認）加速流程，這是危險模式，會讓 AI 不經確認就執行任何指令。要開的話務必全程留在電腦前盯著，不要放著跑一整晚。
  • 大型改動（從零建站、整頁複製）花的時間較長；已有雛形後的小修改很快。

這是從學習庫同步過來的個人筆記。
