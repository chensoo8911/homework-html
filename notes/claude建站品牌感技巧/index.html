Claude Code 建站品牌感技巧

記錄日期：2026-07-16　來源：一支 YouTube 教學影片整理的 5 個技巧 逐步操作版見 Claude網站建置SOP（同一支影片的完整 SOP）。

白話說明

AI 做出來的網站常常有種「一眼看出是 AI 生的」的樣子（版面、字體、配色都很制式）。這篇整理 5 個技巧，讓 Claude Code 做網站時更像有品牌規劃過、不是隨手套模板。可以把它想成：AI 是設計助理，你要給它「品牌規範」跟「檢查機制」，它才不會亂發揮。

工具清單

  • VS Code：主要編輯器
  • Claude Code（VS Code 擴充套件，需 Pro/Max 訂閱）
  • frontend-design skill：官方 plugin marketplace（claude-plugins-official）內建的技能，不用另外裝
  • Puppeteer：讓 AI 自動截圖、比對瀏覽器畫面
  • GitHub：版本控制
  • Vercel：接 GitHub 自動部署
  • 21st.dev／Dribbble／Godly／Awwwards：找視覺靈感的網站

5 個技巧

0. 先設定 CLAUDE.md

把它當作「這個專案的系統提示詞」——寫清楚規則（精簡、不要長篇大論），做的過程中持續補充。就像設計專案的品牌規範文件，越做越完整。

1. 每次寫前端前先呼叫 frontend-design skill

搭配一個 brand_assets 資料夾放 Logo、品牌規範，用 @ 標記餵給 AI 看。這樣輸出會比較專業、不那麼「AI 味」。

2. 截圖迴圈（Screenshot Loop）

設定 Puppeteer 讓 AI 自己截圖比對瀏覽器實際畫面，抓出落差自動修正，不用人一直盯著改。

坑：動態背景動畫這類效果，截圖比對容易讓 AI 卡進無限迴圈——AI 一直覺得「沒做好」，越改越糟。遇到這種情況要明講：「不要用截圖工具比對，直接改程式碼」。

3. 拿別的網站當範本

用瀏覽器開發者工具截全頁 screenshot，再複製它的 CSS 樣式碼，一起丟給 AI「照做一個一樣的」。做完後再套自己的品牌色、Logo、文案。

4. 個別元件借靈感

不整站複製，只針對單一元件（例如按鈕、背景動畫）去 21st.dev 抓程式碼片段，貼給 AI，請它局部整合進某個區塊。

部署流程

GitHub 建 repo → AI push 程式碼 → Vercel 接 GitHub 自動部署 → 本機（localhost）先測試，滿意了才明確叫 AI push 上 GitHub，避免壞版本自動上線。

注意事項

影片示範的「bypass permissions mode」（跳過權限確認）是危險模式，會不經確認執行任何指令。要開啟的話必須全程盯著，不要放著跑一整晚。
