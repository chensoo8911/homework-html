AI與Claude工具 記於 2026-07-23

Claude 權限模式六等級

拆自「Claude運作與設定大全」；比「非工程師從零安裝Claude Code教學」3-5 節的簡版四模式更完整（六種＋切法＋易混淆點）

Claude Code 有六種「權限模式」，決定它每次要動工具（改檔案、跑指令）之前，要不要先問過你。可以想成：這是 AI 助理的「放手程度」旋鈕，跟做專案給新人多少自主權是同一種邏輯——完全不放心就每步都要簽核（Manual），信得過就讓他照流程做完再檢查（Accept Edits），還沒動手前只想先讓他去現場勘查別亂動東西（Plan）。

模式做什麼怎麼切
Manual（預設）每個工具第一次用都問你要不要Shift+Tab 循環
Accept Edits改檔案／常見指令（mkdir、mv…）自動放行Shift+Tab 循環
Plan只能讀、不能動源檔（先探勘再動手）Shift+Tab 或打 /plan
Auto背景有分類器把關，能省的提示才省Shift+Tab 循環
Don’t Ask沒先核准的工具直接拒絕，全自動跑開機參數 --permission-mode dontAsk
Bypass Permissions全部跳過檢查（除了 rm -rf ~ 這種硬防呆）開機參數或寫進 settings.json

怎麼選

  • 一般情況維持 Manual（預設）最安全。
  • 邊改邊審、確定自己會盯著 git diff → 切 Accept Edits。
  • 動手前想先讓 AI 探勘 codebase 結構、不希望誤改 → Plan。
  • 一件信任度高的長任務、懶得一直按確認 → Auto。
  • Bypass Permissions 官方寫死只給「容器／VM 隔離環境」用，一般 Mac 桌面環境用這個等於拆掉所有防呆，不建議用。

容易搞混的兩層，要分清楚

  1. Session 內用 Shift+Tab 切的模式，只在當次對話生效；要永久生效得寫進 ~/.claude/settings.json 的 defaultMode 欄位。
  2. 「permission mode」（上面這張表，管的是工具權限控管）跟「Auto Mode Active」（管的是 AI 該不該停下來問你，行為風格層面，少問、卡關才問）是完全不同層的兩件事——雖然名字都有 Auto，機制不一樣，不要混為一談。
