AI協作與自動化概念

自動化工具三分類（Make.com／n8n、GitHub、Antigravity）

記錄日期：2026-07-16 本篇涵蓋：三大類別總覽、Make vs n8n 比較、GitHub 是什麼、Antigravity 是什麼、自動化工具適不適合跑 agent

把 n8n / Make.com、GitHub、Google Antigravity 放在一起比，其實是三種完全不同用途的工具，容易搞混是因為都跟「自動化 / AI 開發」有關。

三大類別總覽

工具核心用途誰在用類別專有名詞
Make.com / n8n串接 App、自動化流程營運、行銷、一般人iPaaS（整合平台即服務）／workflow automation
GitHub存放與協作管理程式碼工程師、開發團隊VCS hosting / SCM（版本控制託管、原始碼管理）
Google Antigravity用 AI 代理協助寫程式開發者、想用 AI 寫程式的人Agentic Development Platform（代理式開發平台）

一句話總結：Make/n8n 是「串流程」、GitHub 是「存程式碼、做協作」、Antigravity 是「讓 AI 幫你寫程式」。三者可以搭配用——用 Antigravity 寫的程式存進 GitHub，再用 n8n/Make 串接運作。就像設計流程裡，Antigravity 是「畫圖的軟體」、GitHub 是「檔案總管＋版本備份」、n8n/Make 是「印刷廠自動接單流程」，三件事各管各的。

Make.com vs n8n（自動化工具怎麼選）

兩個都是自動化工具，讓你不用寫程式就能把不同 App、服務串接起來，自動完成重複性工作（像設計師串「表單填完→自動存 Drive→自動發 Slack 通知」）。

  • Make.com（前身 Integromat）：視覺化平台，畫布上用「積木」把服務連起來。介面直覺、對新手友善，適合非工程背景。只有雲端服務、非開源。
  • n8n：概念類似但更偏技術、更有彈性。最大差異是開源、可自架（self-host），資料能留在自己伺服器，方便串接自訂 API 與寫程式邏輯。工程師或重視資料隱私、成本控制的團隊常用。
Make.comn8n
上手難度更簡單、純視覺化稍微技術一點
部署只有雲端服務可自架，也有雲端版
開源否是
適合非工程背景、快速上手工程師、重視資料掌控

（兩者常跟 Zapier 比：Zapier 最簡單但較貴，Make 性價比高，n8n 最彈性且能自架省成本。）

GitHub 是什麼

程式碼的儲存與協作平台。工程師用來存放程式碼、做版本控制（記錄每次改動、可回溯）、多人協作、追蹤問題。核心是管理程式碼本身，可想成「程式碼的雲端硬碟＋協作系統」（GitHub Actions 能做自動化，但那是附加功能，不是本業）。

Google Antigravity 是什麼

Google 推出的 AI 代理程式開發平台（IDE），特色是「代理優先（agent-first）」——交代任務後，AI 代理會自己規劃、寫程式、執行、測試、甚至操作瀏覽器驗證結果，並產出任務清單、截圖等可檢視成果。目前公開預覽、個人免費。支援 Gemini 3 Pro、Claude Sonnet 4.5、GPT-OSS。

自動化工具適合跑 agent 嗎？

要看是哪一種 agent，適配程度差很多。

  • 本質差異：自動化工具骨子裡是流程確定性（事先畫好 A→B→C，照跑但不會自己判斷）；真正的 AI agent 是自主決策（給目標，自己想步驟、選工具、看結果決定下一步）。哲學上有點相反。
  • 界線在模糊：n8n、Make 都加了 AI/agent 節點。特別是 n8n 內建 LangChain、AI Agent 節點，可放會自己呼叫工具、多輪推理的 LLM agent，社群很多人拿它當 agent 平台用。Make 也有 AI 模組但彈性不如 n8n。
  • 適合用它跑 agent：有明確流程框架、只在某幾個環節需要 AI 判斷（客服分類、資料整理後讓 AI 決定回覆、智能工作流）。串接現成服務超方便。
  • 不適合：高度自主、長鏈條推理、需複雜記憶與動態規劃的 agent，會綁手綁腳，適合專門框架（LangGraph、AutoGPT 類）或 Antigravity 那種開發平台。

一句話：n8n 拿來跑「有框架的 agent 工作流」很好用；要跑「完全自主的 agent」就會遇到天花板。n8n 明顯比 Make 更適合做 agent。
