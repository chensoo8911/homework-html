commit / push / 發版 / compact 的差別

記錄日期：2026-07-24

一句話總覽

  • commit = 存檔（存本地）
  • push = 上傳雲端（同步 GitHub）
  • 發版 = 正式標記版本（比 push 更慎重）
  • compact = 對話濃縮（跟檔案無關，是 Claude 的記憶瘦身）

1）commit vs push（存檔的兩個地方）

專案有兩個地方在存：你的電腦（本地）＋ GitHub 雲端（遠端）。

  • commit = 把目前改動存成一個「本地存檔點」，像遊戲按存檔，但只存在你這台機器。
  • push = 把本地存檔點上傳到 GitHub 雲端，等於同步到雲端備份。
  • 關鍵：commit 完東西還只在你電腦裡，一定要再 push，GitHub 上才看得到。順序永遠是先 commit 再 push。
  • 實用判斷：「確認目前進度都有存好、之後回得來」→ 正解通常是 commit + push 一起做。

2）發版（release）vs 一般 commit/push

  • commit/push = 日常存檔、上傳雲端，隨時、改一點就能做（很頻繁）。
  • 發版 = 把某個 push 後的狀態正式標記成一個「版本」（v1、v2…），對外公告「這版可以用了」，一個完整段落才發一次（很正式、不常做）。
  • 比喻：commit/push 像平常存草稿、上傳備份；發版像把稿子定稿、蓋章、對外發布並貼上版本號。
  • 發版 = commit/push 再加上：打 tag（貼版本號）＋ 寫 CHANGELOG（這版改了什麼）＋ 建 GitHub Release（正式發布）。不是每次 push 都要發版。
  • 完整 5 步（缺一 GitHub 版本頁會空白）：更新 CHANGELOG → commit → 打 tag → push tag → 建 GitHub Release。

3）compact（完全不同層次）

  • compact 跟 git、跟檔案一點關係都沒有，它是 Claude 這邊的事。
  • commit/push/發版 管的是你的專案檔案；compact 管的是「我們這段對話」的記憶。
  • 當對話聊很久、內容太多，系統會把前面對話壓縮成重點摘要，讓對話能繼續、不會因太長卡住。動的是對話，不是檔案。

這是從學習庫同步過來的個人筆記。
