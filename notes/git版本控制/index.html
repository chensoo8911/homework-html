Git 版本控制

remote（git 遠端）

是什麼：git 幫本機資料夾記住的「遠端網址書籤」，指向 GitHub 上某個 repo 的網址，用一個好記的名字代替一長串網址。

範例：

git remote -v
origin  https://github.com/<個人帳號>/<repo名>.git
sv      https://github.com/<公司帳號>/<repo名>.git
  • origin、sv 是「書籤名」，後面網址才是實際指向的 repo
  • git push origin main → 推去 origin 指的那個 repo
  • git push sv main → 推去 sv 指的那個 repo

比喻：像 Figma 的「共享連結」——設一個書籤名代替一長串網址，之後打書籤名就好，不用每次貼完整網址。

關鍵應用：一個資料夾可以同時設兩個 remote（例如 origin=個人帳號、sv=公司帳號），這樣同一份檔案改一次，就能推去兩個不同的 GitHub 帳號/repo，不用維護兩份檔案。這是「單一 clone、雙 remote」架構的核心機制。

origin 是慣例上的預設書籤名（通常是第一個設定的 remote），sv 是自訂名字，名字本身沒有特殊意義，純粹方便記憶區分。

日常會用到的指令速查

（2026-08-07 記，起因：幫「設計資源」專案 git init 時順手問清楚的）

用這些指令的前提（先講這個，不然抄了也用不出來）

  1. 那個資料夾要先有版控（跑過 git init，或本來就是 clone 下來的）。除了 git init 自己以外，其他指令都要這個前提。
  2. 你人要「站在」那個資料夾裡（先 cd 進去）。git 是看「你現在在哪個資料夾」決定要管哪個專案。

沒有版控的地方打 git status，會回：

fatal: not a git repository (or any of the parent directories): .git

白話＝「這裡不是版控資料夾，往上層找也沒找到」。不是壞掉，是走錯地方了。

⚠️ 它會往上層找：站在 專案/分析/ 裡打指令，上一層 專案/ 有版控的話，它就直接管那個。所以站在子資料夾裡也算數；真正沒版控的是整條路往上都找不到 .git。

怎麼確認：

cd <專案資料夾>
git status

有列出東西＝有版控；回上面那句 fatal ＝沒有。

每天會用到的五個

指令白話什麼時候用
git status我改了什麼還沒存？動手前後都看一眼
git diff具體改了哪幾行？存檔前確認沒改壞
git add .把改動放進「待存區」存檔前的第一步
git commit -m "說明"真正存檔，附一句說明一個段落做完就存
git log --oneline看歷史，一行一筆想找「什麼時候改的」

存檔是兩步（add 再 commit）——像 Illustrator 先選取物件、再套效果：add 是選要存哪些，commit 是按下存檔。

偶爾用到、但一定會遇到

指令白話
git init幫這個資料夾開始做版控（只在本機，跟 GitHub 無關）
git remote -v這個資料夾有沒有連到 GitHub？連去哪？
git push把本機的存檔傳上 GitHub（沒設 remote 就沒得推）
git pull把 GitHub 上別人的改動拉下來
git restore <檔名>這個檔改壞了，退回上次存檔的樣子
git show <代號>看某一筆歷史當時到底改了什麼

兩個關鍵觀念

  • commit ≠ 上傳。commit 只存在自己電腦裡，要 push 才會上網；沒有 remote 的 repo 永遠不會有東西離開這台電腦。
  • .gitignore 是「這些檔不要管」的清單（備份檔、暫存檔、.DS_Store）。
