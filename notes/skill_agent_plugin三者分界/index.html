Skill / Agent / Plugin 三者分界

拆自「自動化名詞關係總圖」第五節（設計工作室總比喻）

（2026-07-10 記，起因：把自己的 9 個 skill 全面體檢後想通的）

你          ＝ 老闆（下需求、驗收、點頭）
Claude 主對話 ＝ 專案經理（PM）
──────────────────────────────
Skill   ＝ 手冊櫃裡的 SOP 手冊 → PM 翻手冊照做；手冊自己不會動
Agent   ＝ 外包的接案助理     → 有自己的腦，派出去做完交報告
Plugin  ＝ 買回來的整套工具包 → 拆開是好幾本手冊＋幾條專線
MCP     ＝ 跟外部軟體的專線   → Illustrator、Figma 那兩條
Hook    ＝ 門口的自動感應器   → 事件發生自動響（音效、開場偵測）

三個最容易混淆的分界

  1. Skill 是「知識」不是「功能」：說「skill 執行了」不精確——是 Claude 讀了 SKILL.md 照做。所以 skill 品質＝說明書寫得好不好；說明書越肥，每次翻越花力氣（實際經驗：一支 skill 從 317 行瘦到 149 行，就是這個原因）。
  2. Agent 和主對話的差別只有一個：記憶隔離。Agent 一樣是 Claude、一樣能用工具、一樣能讀 skill——差在它有自己的 context、看不到主對話。這既是限制（要存「對話裡的內容」它辦不到），也是價值（大量讀取不弄髒主對話；驗收時「沒看過製作過程」反而公正）。
  3. Plugin 和 skill 是「包裝 vs 內容物」：拆開 figma plugin，裡面就是十幾個 skill＋一條 MCP 線。裝 plugin＝一次獲得一批 skill；自製 skill 沒有盒子直接放櫃上，本質一模一樣，差別只在「自己寫 vs 商店裝」。

關係一句話

Plugin 是盒子，裡面裝 skill；skill 是說明書，教 Claude 做事；Claude 照著做，遇到大量工作就派 agent；agent 帶著 skill 的知識出門，做完回報一句結論。

另外：「主動現身 vs 手動觸發」跟類型無關——由 description（說明文字）怎麼寫決定，三種都可主動可手動。
